# Jaiyq — EO зерттеу қызметі

> ⚠️ **Бұл қызмет сайттың өнімдік нұсқасына қосылмаған және қосылмайды.**
> Ол — ашық remote-sensing модельдерін жергілікті сынап көруге арналған
> зерттеу құралы.

## Неге өнімге қосылмаған

**1. Техникалық себеп.** Сайт Vercel-де жүреді, бұл қызмет — сенің
машинаңдағы `localhost:8008`. Vercel функциясы оған жете алмайды. Яғни
`ML_SERVICE_URL=http://localhost:8008` тек `npm run dev` кезінде ғана
мағыналы.

**2. Мазмұндық себеп — маңыздырағы.** `AdaptLLM/remote-sensing-Qwen2-VL-2B`
моделі remote-sensing **VQA** деректерінде оқытылған: «жолда неше көлік
бар?», «ғимарат бар ма?». Ол мұнай ластануын, заңсыз қоқысты немесе жер
деградациясын анықтауға оқытылмаған. Ондай сұрақ қойсаң — сенімді
естілетін, бірақ негізсіз мәтін жазып береді.

Оның үстіне кіріс Mapbox RGB тайлы: түсі эстетика үшін түзетілген,
түсірілім күні белгісіз, спектр каналдары жоқ. Одан ластану туралы
қорытынды шығару физикалық тұрғыдан мүмкін емес.

Жобаның басты қағидасы — **ойдан дерек жасамау**. Валидацияланбаған 2B
модельдің «мұнай ластануы байқалады» деген мәтіні дәл сол қағида тыйым
салатын нәрсе. Сондықтан промпт әдейі шектелген: модельден **тек көрінетін
беткі қабат элементтерін** сипаттау сұралады, ешқандай экологиялық диагноз
сұралмайды. Жауапта `caveat` өрісі әрқашан қайтарылады.

## Оның орнына өнімде не жұмыс істейді

**`/api/flood-extent`** — Sentinel-1 SAR радарымен **өлшенген** су ауданы
(км²), аймақ бойынша бөлінген, CSV экспорты бар. Ол нейрожелі емес,
Copernicus EMS қолданатын классикалық радар табалдырығы. Түсіндірмесі
[`src/lib/floodSar.ts`](../src/lib/floodSar.ts) ішінде.

Айырмашылығы: «суретте су көрінеді» деген сөз емес, «47.3 км² су басты,
өлшеу күні 12 сәуір» деген **сан**. Экологтың есебіне қоюға жарайды.

## Не түзетілді (бастапқы нұсқамен салыстырғанда)

| Мәселе | Болған | Болды |
|---|---|---|
| **SSRF** — кез келген URL жүктелетін | шектеу жоқ | хост тізімі: `api.mapbox.com`, Sentinel Hub |
| **CORS** | `allow_origins=["*"]` — браузердегі кез келген бет шақыра алатын | тек `localhost:3000` |
| **Жады** | MPS-те `float32` → 2B модель ~8.8 ГБ RAM, MacBook Air-да swap | `bfloat16` → ~4.4 ГБ |
| **Тыңдау адресі** | `0.0.0.0` — бүкіл жергілікті желіге ашық | `127.0.0.1` |
| **Сурет көлемі** | шек жоқ, OOM мүмкін | 12 МБ / 16 Мпиксель |
| **Тәуелділіктер** | `transformers>=4.45` жоғарғы шексіз | `<5.0` — жаңа мажор нұсқа API-ды бұзбауы үшін |
| **Промпт** | ластану/қоқыс/деградация сұралатын | тек көрінетін беткі элементтер |
| **Жауап** | ескертусіз | `caveat` өрісі міндетті |
| **Бірінші сұраныс** | модель жүктелгенше бұғатталатын | бірден 503, `/health` арқылы тексеру |

## Орнату

```bash
cd eo-service
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
uvicorn app:app --host 127.0.0.1 --port 8008
```

Apple Silicon-да `torch` MPS-ті автоматты пайдаланады. Бірінші `/describe`
сұранысында салмақтар (~4.4 ГБ) жүктеліп, `~/.cache/huggingface`-де қалады.

```bash
curl http://127.0.0.1:8008/health
```

## Неге TerraMind / Prithvi қосылмады

Бұл талдау бастапқы нұсқада дұрыс жасалған, сақтап қоямыз:

- **TerraMind-base-Flood** — 4 уақыт кесіндісі × (Sentinel-2 12 арна +
  Sentinel-1 RTC 2 арна + DEM) кірісін талап етеді. Бұл толыққанды
  геодерек құбыры (co-registered, бұлтсыз, нормаланған), API шақыруға
  сыймайды.
- **Prithvi-EO-1.0-sen1floods11** — ескі `mmcv`/`mmsegmentation` стегін
  қажет етеді; CUDA/Linux-қа бейімделген, Apple Silicon-да сенімді
  орнатылмайды.

Екеуі де GPU-лы бөлек серверді (HF Inference Endpoints, Modal, RunPod)
талап етеді.

**Бірақ маңызды түйін:** су тасқыны ауданын өлшеу үшін бұл модельдер
**қажет емес** болып шықты. Радар табалдырығы (`/api/flood-extent`) сол
нәтижені GPU-сыз, тегін, сайттың ішінде береді. Нейрожелі керек болатын
жер — су мен құрғақ сорды ажырату дәлдігін арттыру, ал оны біз тірек
кезеңмен салыстыру арқылы шештік.
