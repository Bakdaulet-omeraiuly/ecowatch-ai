# JAIYQ-ML — ауа сапасының кеңейтілген болжам моделі

Атырау қаласы үшін метеорологиядан ауа сапасын (EU AQI, PM₂.₅) болжайтын
градиенттік бустинг моделі. Оқыту Python-мен (осы папка), болжам —
TypeScript-пен Next.js ішінде (`src/lib/ml/`, `src/app/api/ml-forecast`).

## Не үшін керек

Copernicus CAMS ауа сапасы болжамы **~5 күнмен** шектеледі, ал ауа райы
болжамы **16 күнге** дейін жетеді. Модель «метеорология → ауа сапасы»
байланысын Атырау үшін үйренгендіктен, болжамды CAMS шегінен әрі —
**11 күнге** дейін жалғастырады. Бұл CAMS-ты қайталау емес, оны созу.

## Дерек көздері (бәрі нақты, тегін, кілтсіз)

| Не | Көз | Қолданысы |
|---|---|---|
| EU AQI, PM₂.₅, PM₁₀ | Open-Meteo Air Quality Archive (Copernicus CAMS реанализі) | мақсатты айнымалы |
| Температура, ылғал, қысым, жел, бұлт, жауын, шекаралық қабат, 850 гПа T | Open-Meteo Historical Weather Archive (ECMWF ERA5) | белгілер |
| Сол айнымалылардың болжамы | Open-Meteo Forecast API (ECMWF) | нақты болжам жасау |

Оқыту кезеңі: **2022-08-01** (CAMS реанализінің басы) — бүгіннен 7 күн бұрын
(ERA5 кідірісі). Шамамен 30 000+ сағаттық жазба.

## Адал ескерту

> Модель CAMS реанализінде (жаһандық атмосфералық модель) оқытылған, жер
> бетіндегі өлшеу станцияларында емес. Сондықтан ол CAMS мінез-құлқын
> метеорологияға сүйеніп жалғастырады — валидацияланған сенсор өлшемі емес.

Дерек көзі қолжетімсіз болса, оқыту тоқтайды және модель файлы
жаңартылмайды. `/api/ml-forecast` мұндайда **503** қайтарады — жалған дерек
ешқашан көрсетілмейді.

### Дәлдік қақпасы (`usable`)

Модель маусымдық климатологияны MAE бойынша кемінде **5%** жеңуі керек
(`config.MIN_SKILL`). Жете алмаса — модель файлына `usable: false` жазылады
да, `/api/ml-forecast` **503** қайтарады, дашбордта болжам көрсетілмейді.

Себебі анық: климатологиядан артық ештеңе білмейтін модельді «AI болжам» деп
көрсету — жалған дәлдік. Ол жобаның «тек шынайы дерек» қағидасын бұзады.
Қақпа автоматты: апта сайынғы қайта оқытуда дәлдік талапқа жетсе, болжам
өздігінен қосылады.

### Нәтижелер тарихы (2026-08-01, бәрі нақты деректе)

| Нұсқа | Не өзгерді | EU AQI шеберлігі | PM₂.₅ шеберлігі | Қақпа |
|---|---|---|---|---|
| v1.0 | базалық GBT, 250 ағаш | −0.7% | +1.1% | ❌ |
| v1.1 | ауытқу тәсілі, ерте тоқтату, L2 | +2.3% | −1.2% | ❌ |
| v1.2 | адвекция белгілері (20→27) | **+4.3%** | −2.6% | ❌ |

Үш нұсқада да қақпадан өтпеді, сондықтан сайтта болжам **көрсетілмейді**.

**Не үйрендік.** Адвекция белгілері (850 гПа жел, 500 гПа геопотенциал) EU AQI
үшін нақты пайда берді: шеберлік +2.3% → +4.3%, R² 0.046 → 0.145. Яғни
гипотеза дұрыс — Атыраудағы ластанудың бір бөлігі шынымен алыстан келеді.
Бірақ 5% шегіне жетпеді.

PM₂.₅ керісінше нашарлады. Оның себебі — **тарату ығысуы (distribution
shift)**: тексеру кезеңінде (2025-10 … 2026-07) PM₂.₅ деңгейі оқыту
кезеңіндегі маусымдық үлгіден жүйелі түрде ерекшеленеді. Мұны климатологияның
өзінің теріс R² көрсеткішінен көруге болады — яғни мәселе модельде емес,
кезеңдер арасындағы айырмашылықта.

**Келесі не істеуге болады** (әлі жасалмаған):
- Мақсатты `log(PM₂.₅)` қылу — оң қисық таралуға жақсырақ келеді
- Тексеру кезеңін жылжымалы қылу (walk-forward), бір ғана кезеңге тәуелді болмау
- Жер бетіндегі станция деректерін (Qazhydromet/WAQI) мақсат ретінде жинай
  бастау — CAMS реанализі емес, нақты өлшем. Бұл ең дұрысы, бірақ тарихи
  деректің жиналуын күтуді талап етеді.

Қақпа орнында тұрғандықтан, бұл жұмысты асықпай жалғастыруға болады: дәлдік
талапқа жеткен күні болжам сайтта **өздігінен** пайда болады.

## Белгілер (20)

`t2m, rh, dew, psfc, precip, cloud, wspd, wgust, wdir_sin, wdir_cos, blh,
t850, inversion, vent, precip24, wspd24, hour_sin, hour_cos, doy_sin, doy_cos`

Физикалық негізі: **inversion** (`t850 − t2m`) — температуралық инверсия
ластануды жер бетіне қамайды; **vent** (`blh × wspd / 1000`) — желдету
индексі, ауаның таралу қабілеті; **precip24** — жауынмен шайылу;
**wspd24** — тоқырау (stagnation) көрсеткіші.

## Модель

Гистограммалық градиенттік бустинг (квадраттық шығын), тек `numpy`-мен
жазылған — сыртқы ML кітапханасы жоқ. Себебі шығарылатын JSON форматы толық
бақылауда болуы керек: дәл сол ағаштарды `src/lib/ml/gbt.ts` қайта оқиды.

**Маңызды тәсіл — климатологиядан ауытқу.** Модель абсолют AQI-ды емес,
маусымдық климатологиядан (ай, сағат бойынша орташа) **ауытқуды** болжайды:

```
болжам = климатология(ай, сағат) + модель_ауытқуы(метеорология)
```

Себебі: маусымдық және тәуліктік циклды ағаштарға қайта үйретудің қажеті жоқ
— олар тек метеорологиялық ауытқуға шоғырланады. Әрі базалық болжам мен
модель дәл бір негізде салыстырылады, сондықтан ML-дің қосқан құны айқын
өлшенеді.

**Overfitting тежегіштері:** валидация жиынында ерте тоқтату (`patience=40`,
ағаштар ең жақсы итерацияға дейін қиылады), жапырақ L2 регуляризациясы
(`l2=20`), `min_samples_leaf=60`. Гиперпараметрлер — `config.py`.

## Іске қосу

```bash
cd ml-service
pip install -r requirements.txt

python selftest.py   # интернетсіз — алгоритмді тексеру
python train.py      # интернетпен — нақты деректе оқыту
```

Нәтиже:
- `src/data/models/aqi-model.json` — сайт қолданатын модель
- `ml-service/report.md` — дәлдік есебі (MAE, RMSE, R², базалықпен салыстыру)

## Автоматты жұмыс

`.github/workflows/ml-retrain.yml` — **әр жексенбі** модельді нақты деректе
қайта оқытып, өзгерсе коммиттейді. Vercel сол коммитті автоматты деплойлайды.
Қолмен де қосуға болады: GitHub → Actions → «JAIYQ-ML қайта оқыту» → Run.

Сайттағы `/api/ml-forecast` сағат сайын кэштеледі (`revalidate = 3600`),
яғни болжам сағат сайын жаңарады, ал модель апта сайын.

## Дәлдікті бағалау

Хронологиялық бөліну (кездейсоқ араластыру ЖОҚ — уақыттық қатар үшін дұрысы
осы):

| Бөлік | Үлесі | Не үшін |
|---|---|---|
| Оқыту | 68% | ағаштарды өсіру, климатология кестесі |
| Валидация | 12% | ерте тоқтату (қай ағашта тоқтау) |
| Тексеру | 20% | соңғы, бір рет қана қолданылатын баға |

Климатология **тек оқыту бөлігінен** құрылады — валидация мен тексеру
деректері ағып кетпейді.

Базалық болжам — сол климатологияның өзі. «Шеберлік» (skill) =
`1 − MAE_модель / MAE_базалық`. Модель `usable` болу үшін бұл ≥ 0.05 болуы
керек.

Нақты сандар `report.md` ішінде — оқыту жүргеннен кейін пайда болады.

## Файлдар

| Файл | Не істейді |
|---|---|
| `config.py` | координаттар, айнымалылар, гиперпараметрлер, `MIN_SKILL` |
| `fetch.py` | нақты архивтерді жүктеу (жыл бойынша, қайталаумен) |
| `features.py` | белгілер құрастыру — **`src/lib/ml/features.ts` көшірмесі** |
| `climatology.py` | маусымдық орташа — **`src/lib/ml/climatology.ts` көшірмесі** |
| `model.py` | гистограммалық градиенттік бустинг + ерте тоқтату (numpy) |
| `train.py` | толық құбыр: жүктеу → оқыту → бағалау → қақпа → экспорт |
| `selftest.py` | интернетсіз тексеру (алгоритм, JSON, ерте тоқтату) |
| `parity_check.py` | Python ↔ TypeScript дәл сәйкестігі (Node керек) |

⚠️ `features.py`/`features.ts` және `climatology.py`/`climatology.ts` жұптары
**әрқашан бірдей** болуы керек. Біреуін өзгертсең — екіншісін де өзгерт.
`parity_check.py` мұны әр CI жүрісінде тексереді.
